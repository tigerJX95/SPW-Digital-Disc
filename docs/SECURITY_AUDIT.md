# SPW Digital Disc V1.15.0 图片读取与资源释放审计

本次审查以 V1.15.0-test.4为基线，重点检查专辑封面和自定义盘面从文件读取、解码到缓存、绘制及释放的过程。以下两项均在 test.4 插件包中的已编译代码上通过离线回归重现。

## 专辑取景预览的原图像素上限

修复前，取景窗口使用 ImageIO 读取图片时只检查单边尺寸。另一条 Skia 预览路径还检查原图总像素。两条路径因此会对同一尺寸作出不同判断。即使缩略图只需 42 像素，文件仍可能进入超出预算的解码工作。实际耗时和峰值内存取决于格式和解码器，本次没有测量宿主内存峰值。

修复位于 `FramingAlbumLibrary.decode` 和 `LocalDiscService.allowedDimensions`。当 ImageIO 已读到尺寸并确认超限时，直接跳过该候选封面。Skia 回退在生成预览前也检查相同上限。封面尺寸按原图计算，允许单边至 8192 像素，总量至 16,777,216 像素。文件长度上限为 32 MiB。

`FramingAlbumLibraryTest` 用标准 ImageIO 写出两张普通 PNG，再通过实际预览入口生成 42 像素缩略图。4096 × 4096 正好达到预算，仍可显示。4097 × 4096 超过预算，test.4 仍返回缩略图，正式版会跳过。

## 解码完成后宿主回调异常时的资源释放

本地盘面解码结束时，插件会再向宿主核对当前曲目，避免切歌后把旧盘面显示到下一首歌。test.4 在这个回调抛出异常时，既未将新图交给缓存，也漏掉了关闭操作。如果反复发生，未及时释放的图片资源可能累积。

修复位于 `LocalDiscService.scan`。解码结果在成功交给缓存前由当前读取操作负责释放。若无法确认播放曲目，本轮放弃发布，下一次正常扫描可以重试该文件。进入缓存后，由缓存负责淘汰、替换和停用时的释放。

`LocalDiscServiceTest` 从磁盘读取有效 PNG，在解码结束后的曲目核对处模拟一次宿主异常。测试检查首张图片恰好关闭一次、失败当次没有盘面可绘制、下次扫描能读回同一文件，以及停用后第二张图片也恰好关闭一次。

## 其他检查与验证边界

- 源码复核包括自定义盘面候选文件名、专辑分盘目录向上一级查找的条件、文件打开时对末级符号链接的处理、缓存条数与字节预算、停用时的后台任务清理，以及诊断日志的队列和文件大小限制。
- 离线回归覆盖文件替换与删除、跨专辑缓存复用、解码期间切歌和停用、迟到的解码结果、分盘父目录封面及布局和动画逻辑。两组测试中的部分程序重复，结果分别统计。
- 回调异常由测试注入，资源释放用可计数的图片对象验证。此测试覆盖插件的释放逻辑，宿主的原生内存峰值未纳入测量。

v1.15.0 使用 SPW 1.19.3 Microsoft Store 宿主归档进行构建接口检查。56 个离线回归程序通过，其中 15 个核心程序也通过了独立入口的检查。
