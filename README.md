# SPW 数字化碟片插件

[中文](README.md) | [English](README_EN.md)

为 Salt Player（椒盐播放器，简称 SPW）增加“完整专辑封面＋右侧 CD”的数字唱片展示效果。

当前版本：**v1.6.0**

- **自定义盘面查找顺序**：可在插件设置中调整 `cd.png`、`cd.jpg`、`disc.png`、`disc.jpg` 的查找顺序。
- **当前盘面来源**：排序窗口显示当前曲目选中的盘面文件或回退来源，切歌时自动刷新。

[更新历史](CHANGELOG.md)

## 项目由来

这个插件的灵感来自 [**Georgia-ReBORN**](https://github.com/TT-ReBORN/Georgia-ReBORN)——我经常使用的 foobar2000 主题。

我很喜欢它将专辑封面与碟片一起呈现的方式。曾经，我也是实体唱片的收藏者，喜欢拿起一张唱片、欣赏封面和盘面的感觉。但实体 CD 的保存并不容易，即使认真保管，随着年份增长，也难免面临老化和损伤。对我而言，数字化是更适合长期收藏与日常欣赏的方式。

于是，我想把这种数字唱片的展示体验带到椒盐播放器：在享受数字音乐便利的同时，也保留一些收藏和欣赏实体唱片的乐趣，并把它分享给同样喜欢这种感觉的人。

## 目前功能

- **一级详情页**：保留 SPW 原生专辑封面、歌词及播放控制。
- **二级展示页**：点击专辑封面后，放大并居中展示完整封面与右侧 CD；封面不会被挤压成半张图片。
- **自定义盘面**：在当前歌曲所在目录中，按下表的默认顺序或设置中的自定义顺序查找；高优先级候选无法解码时继续尝试下一项。
- **自动生成盘面**：没有可用自定义盘面时，将专辑封面副本裁成圆形 CD，并绘制白色窄边、淡白半透明中心孔和半透明压环。压环主体保持半透明，内外两道细银环以相邻的亮面和暗槽表现轻微金属质感，保留封面细节和中心小白点；前方专辑封面仍完整显示。
- **无封面回退**：宿主完成封面读取且没有可用专辑封面时，使用原生占位封面与银白色空白 CD；有可用自定义盘面时优先使用。以 SPW 的有效封面及读取结果为准，不限定专辑封面文件名，也不按等待超时判定缺失。
- **透明图片支持**：使用自定义 PNG 时，保留图片已有的透明背景、半透明像素与中心孔，并对画布外沿施加抗锯齿圆形遮罩；不额外挖中心孔或叠加压环。
- **跨专辑盘面缓存**：自定义盘面最多缓存 4 张，归一化像素预算合计不超过 32 MiB（包含当前盘面）；超限时淘汰最久未使用的图片。返回专辑前重新检查候选优先级、文件大小、修改时间及可用的文件标识，文件变化或删除后重新处理；停用插件或当前媒体清空时释放。默认封面仍依照宿主有效结果处理。
- **播放联动旋转**：插件设置中开启“播放时旋转碟片”，出碟完成后约 240 ms 柔和起转，标准档稳定后约 20 秒一圈；暂停与收碟冻结，恢复时从原角度起转。默认关闭，封面保持静止。
- **碟片前置展示**：在插件设置中开启后，CD 绘制在封面前方；默认关闭。前置动画使用完整圆盘移动与短暂整体淡入淡出；建议出碟量设在 50 附近比较；前置时出碟量控制向右移出距离，0 仍仅封面。
- **出碟量设置**：插件管理中打开 SPW Digital Disc 的设置入口，调节 0–100；默认 50 保持原效果，100 显示完整盘面。设置由宿主保存；组合画面自动适配窗口，0 值返回无需等待收碟。
- **页面动画**：封面先放大，随后 CD 从封面后方渐进滑出；点击组合画面返回时先收碟，再调用原生返回操作。倒影跟随同一进度；正常切歌会重新出碟，但不重复缩放封面；快速连切只为最后稳定选择的歌曲出碟。
- **组合倒影**：为封面与 CD 绘制短幅、向下渐隐的倒影。
- 以只读方式读取本机或系统可访问的网络共享中的盘面图片，保留歌曲和盘面原图。自动生成的盘面仅用于显示。

## 安装与使用

以下为 **V1.6.0** 的安装步骤。Microsoft Store 版的接口映射覆盖 SPW 1.19.0 与 1.19.3。Windows 和 Ubuntu 26.04.1 LTS（Linux）的 Steam 版实测记录见[已验证的 SPW 宿主版本](#已验证的-spw-宿主版本)。插件使用 SPW 内部绘制接口，SPW 后续版本升级可能需要重新适配。

1. 准备编译好的 `.spmod` 文件。源码 ZIP 不能直接作为插件安装；自行构建的方法见下文。
2. 在 SPW 的插件管理中，使用本地插件导入入口选择 `.spmod` 文件。
3. 按宿主提示授予 `class-transform` 和 `library-read` 权限，然后启用插件、重启 SPW。
4. 播放一首来自本机或已连接网络共享的歌曲，点击底部播控条进入一级详情页，再点击专辑封面进入二级展示页。
5. 二级页点击封面/CD 组合画面返回：CD 先收回，再回到一级页。出碟中也可以点击返回；重复点击不会叠加返回请求。

标准档出碟约 700 ms、完整收碟最多约 650 ms，起止采用五次缓动；末尾不足一个物理像素的位移可提前结束，随后执行原生返回。出碟中途返回时承接当前姿态，最多约 80 ms 制动后收回；盘面保持在原终点以内，完整展开后返回不增加制动等待。

切歌后等待约 280 ms 的选择稳定期，并确认封面与盘面查询就绪后播放出碟；这段时间继续切歌会替换待播放请求，不逐首补播。封面来源接管后不会再接受当前切换中的旧节点的反向覆盖。收起到播控条后重新展开时，等待宿主展开完成，再重新播放封面优先和出碟动画；展开过程不消耗动画时间。

直接收起整个播放详情页或停用插件时，会取消未完成的动画与延迟返回，避免残留到迷你播放栏。

## 自定义盘面图片怎么放

> [!IMPORTANT]
> **音频和自定义盘面必须是同一个文件夹里的普通文件。** 文件夹可以位于本机、映射的网络驱动器或可访问的 UNC 共享。插件查找盘面时会跳过音频文件或盘面文件的符号链接。

例如，音频放在 `D:\Music\某张专辑\01.flac` 时，盘面应放在 `D:\Music\某张专辑\cd.png`。音频放在 `\\NAS\Music\某张专辑\01.flac` 时，盘面应放在 `\\NAS\Music\某张专辑\cd.png`。

| 优先级 | 文件名 |
| --- | --- |
| 1 | `cd.png` |
| 2 | `cd.jpg` |
| 3 | `disc.png` |
| 4 | `disc.jpg` |

默认优先使用第一个可读取并解码的盘面。建议按表中的小写文件名命名，同目录歌曲共用该盘面。访问权限沿用运行播放器的系统账户。HTTP/HTTPS 流媒体地址不参与盘面查找。

在插件设置中点击「自定义盘面查找顺序」，上下拖动四行文件名。越靠上越先查找，点击「确认」后生效。「恢复默认」会在窗口中还原表里的顺序。窗口底部显示当前曲目盘面的来源，例如「使用自定义图片 cd.png」或「由专辑封面生成（CD 样式）」。排序设置对所有曲目生效。

需要透明背景或透明中心孔时，请使用已处理好的 PNG。

主要支持与测试范围为 **1000 × 1000 至 4000 × 4000 像素**，包括 3000 × 3000 的自定义 PNG。显示副本最多缓存为 **2048 × 2048 像素**，较小图片不放大；原图不修改。默认盘面使用宿主封面的独立副本，自定义盘面在后台归一化，并在同目录或跨专辑返回时经文件检查后复用。缓存预算只针对保留的自定义盘面像素，不包含临时解码开销、宿主封面或其他播放器内存。文件超过 32 MiB、单边超过 8192 像素或总像素超过 16 Mi 像素时拒绝读取；超过 4000 × 4000 的图片不属于主要支持与测试范围。

解码前会根据图片像素格式和 JVM 堆上限估算像素缓冲区开销。开销过高时会在解码阶段抽样，继续生成最长边不超过 2048 像素的显示副本。

## 制作自定义 CD 图片（可选）

> [!NOTE]
> **使用 PSD 模板制作盘面**
>
> [下载 cdArt_Template.psd](templates/cdArt_Template.psd)。这是用于制作数字化 CD 盘面的 Photoshop 模板，画布尺寸为 **1000 × 1000 像素**。模板包含圆形外沿、中心孔、压环和可选明暗效果，便于将盘面扫描图、照片或自定义图案整理为适合播放器展示的透明 PNG。
>
> 1. **打开模板并另存副本**，保留原始 PSD，方便之后重复使用。
> 2. **选择盘面样式**：在包含 `YOUR IMAGE HERE` 占位层的样式组中选择一种，开启该组并关闭其他同类样式组。
> 3. **放入图片**：将图片置入所选组内，替换占位层的位置，保留组上的蒙版。等比缩放、移动图片，使图案覆盖盘面区域；避免拉伸变形。
> 4. **调整视觉效果**：按需调整 `Shading` 明暗组及 `Optional` 可选效果的可见性和不透明度，使中心压环、外沿与图片自然融合。
> 5. **检查透明区域**：可临时开启 `Test Colours` 背景检查组，观察深浅背景下的边缘和中心孔。导出前关闭该组及 `test sizes and basic rules` 辅助层，确保圆盘外部和中心孔保持透明。
> 6. **导出 PNG**：保持 **1000 × 1000 像素**，启用透明度，导出为 `cd.png`，放入音频文件所在的同一文件夹。
>
> PSD 用于编辑，播放器实际读取导出的 PNG。同时保留可编辑的 PSD 副本，便于后续修改。


## 设置

在插件管理中打开 SPW Digital Disc 的设置入口。设置由宿主保存并在重启后恢复。

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| 自定义盘面查找顺序 | 上表顺序 | 打开窗口，拖动四种盘面文件名来调整优先级 |
| 出碟量 | 50 | 范围 0–100；0 仅封面，100 完整移出；控制盘面向右移出的距离 |
| 碟片前置展示 | 关闭 | 控制重叠区域的前后层级，与出碟量独立 |
| 播放时旋转碟片 | 关闭 | 出碟完成后柔和起转，标准档稳定后顺时针约 20 秒一圈；暂停冻结、恢复续转 |
| 出收碟速度 | 标准 | 慢速、标准、快速，调整封面过渡及碟片滑出和收回的时间 |
| 碟片旋转速度 | 标准 | 开启旋转后生效，慢速、标准、快速分别约 30、20、12 秒一圈 |

前置模式在运动中保持完整圆盘，并在起步、收尾做短暂整体淡入淡出。前置与后置使用相同位移；出碟量 100 时盘面与封面几乎不重叠，两种层级差异很小。原生滑块可能显示小数，绘制时取整为百分比，例如 `50.062717` 按 50 处理。

旋转仅作用于盘面，封面保持静止，倒影同步。每次起转用约 240 ms 从静止平滑加速，之后按所选速度旋转，标准档约 20 秒一圈；暂停或开始收碟时立即冻结当前角度，恢复播放时从原角度柔和起转，不补算暂停时间。切歌后的新盘从初始角度开始；出碟、收碟和出碟量 0 时不转。二级页收起到迷你播放条后冻结，重新展开并完成出碟后续转；返回一级页后再次进入二级页，从初始角度开始。关闭旋转会恢复初始方向。

## 兼容性与限制

- 已内置 SPW 1.19.0／1.19.3 的绘制与状态校验配置。封面入口相关的三类及封面绘制器支持动态定位；绘制器仍受规范化代码指纹约束，页面状态与播放、封面加载流程的其他关键类保留原有指纹校验。
- 盘面仅在音频所在目录按允许的文件名查询，不递归、不支持自定义搜索路径，也不自动下载。
- 自定义 JPG 仅处理外部圆形轮廓，不自动识别图内背景、中心孔或盘面主体。
- 播放状态读取不可用时停止旋转，日志记录 `ROTATION_STATE_UNAVAILABLE`；封面与盘面展示继续使用原逻辑。
- 不同窗口、显示缩放及快速页面操作的兼容性依赖宿主，问题可通过仓库 Issue 模板报告。

## 编程方式

插件使用 **Java**，沿用 SPW 插件 API、Compose 绘制体系及 Skia 图片解码。通过已定位的 `FullScreenCover` 入口接入，在独立 Canvas 中绘制完整封面与 CD；盘面图片异步读取，原生封面与自定义画面通过 Compose 可观察状态衔接。

## 从源码编译并生成安装包

以下步骤用于自行生成 `.spmod` 插件。仅安装和使用已经编译好的插件时，无需配置这些开发工具。

### 1. 准备构建环境

| 项目 | 要求与用途 |
| --- | --- |
| JDK | JDK 25，须包含 `java` 和 `javac` |
| Gradle | 安装 Gradle 9.8 |
| Python | Python 3，Windows 下须能以 `python` 命令运行 |
| SPW 宿主文件 | 已适配的 SPW 1.19.0 或 1.19.3 Microsoft Store 安装目录中的 `app\ffmpeg-x64.dll` |

宿主文件必须自行从对应 SPW 安装目录提供，不能使用通用 FFmpeg 的同名 DLL 替代。宿主及开发工具不随源码包分发。

### 2. 解压源码并配置 Windows 环境

完整解压源码 ZIP，进入包含 `build.cmd`、`build.gradle`、`MANIFEST.MF` 和 `src` 的目录。不要直接在压缩包中运行脚本。

打开 **命令提示符（CMD）**，按实际安装位置设置环境变量。以下路径仅为示例：

```bat
set "JAVA_HOME=C:\Tools\jdk-25"
set "PATH=%JAVA_HOME%\bin;C:\Tools\gradle-9.8.0\bin;%PATH%"
```

`JAVA_HOME` 指向 JDK 根目录，不是其 `bin` 子目录。上述设置仅影响当前 CMD 窗口；Python 安装目录也需在 `PATH` 中。

检查工具是否可用：

```bat
java -version
javac -version
gradle --version
python --version
```

确认 Java / javac 为 25，Gradle 为 9.8，且 Gradle 显示的运行 JVM 为预期 JDK。若提示命令不存在，先检查安装路径和 `PATH`。Windows 下仅能运行 `py` 而不能运行 `python` 时，需要先修正 Python 的命令路径；现有构建脚本调用的是 `python`。

### 3. 执行编译

在同一个 CMD 窗口中切换到解压后的源码目录，例如：

```bat
cd /d "D:\Projects\SPW-Digital-Disc"
build.cmd "C:\你的SPW安装目录\app\ffmpeg-x64.dll"
```

把第二行的宿主路径替换成真实路径，路径含空格时保留双引号。脚本会调用 Gradle 的 `plugin` 任务，检查宿主组件、编译 Java 源码并打包插件。字节码目标保持为 Java 21，宿主仅作为 `compileOnly` 依赖，不会被打入插件。

若使用 PowerShell，先配置好同样的环境变量，在源码目录执行：

```powershell
.\build.cmd "C:\你的SPW安装目录\app\ffmpeg-x64.dll"
```

`build.cmd` 需要宿主路径参数，不会自动安装开发工具；直接双击不会完成构建。重新生成安装包时，修改源码后再次运行同一条命令即可。

### 4. 找到生成的插件并安装

构建显示 `BUILD SUCCESSFUL` 后，在源码目录的 `dist` 文件夹中找到：

```text
SPW_Digital_Disc_v1.6.0.spmod
```

这就是可供 SPW 导入的插件安装包，无需再将整个源码目录压缩或更改后缀。`build` 目录是编译中间产物，不是安装包。

从 SPW 插件管理中导入此 `.spmod`，授予 `class-transform` 和 `library-read` 权限，启用后重启 SPW。具体页面操作和盘面文件放置方法见本文前面的“安装与使用”和“自定义盘面图片怎么放”。

### Linux 下编译

配置 `JAVA_HOME`、将 JDK 和 Gradle 的 `bin` 加入 `PATH`，确保 `python3` 可用，在源码目录运行：

```sh
bash build.sh "/path/to/SPW/app/ffmpeg-x64.dll"
```

同样需要对应的 SPW Windows 宿主文件，产物也位于 `dist/`。构建平台与宿主兼容性是两件事，运行时仍按宿主内部接口匹配适配配置；已验证版本见上表。

### 常见构建问题

| 提示或现象 | 处理方法 |
| --- | --- |
| `Set JAVA_HOME` | 将 `JAVA_HOME` 指向已安装 JDK 25 的根目录 |
| `gradle` / `python` 不是可识别命令 | 安装对应工具并配置 `PATH`，在同一终端重新执行 |
| `Usage: build.cmd ...` | 缺少宿主路径参数，按上面的完整命令调用 |
| 宿主文件不存在或无法作为 ZIP 读取 | 检查是否指向对应 SPW 的 `app\ffmpeg-x64.dll`，而非其他同名文件 |
| `fingerprint mismatch`、缺少宿主类或接口相关编译错误 | 宿主可能不是当前适配版本；使用匹配版本，不要跳过检查强行构建 |
| 构建失败但 `dist` 中已有旧文件 | 以 Gradle 的退出状态判断构建是否成功 |

构建前校验使用宿主归档及关键类的 SHA-256 指纹，并按签名解析封面入口和目标方法，验证唯一的静态调用点。
