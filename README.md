# SPW Digital Disc

[中文](README.md) | [English](README_EN.md)

为 Salt Player for Windows（椒盐播放器 Windows 版，简称 SPW）增加“完整专辑封面＋右侧 CD”的数字唱片展示效果。

当前版本：**V1.0.0**，适用于 **SPW 1.19.0 Microsoft Store**。

本版在原有封面与 CD 展示、本地盘面读取基础上，加入页面出碟/收碟、切歌动画、快速连切保护、重新展开处理及半透明中心压环。

## 项目由来

这个插件的灵感来自 [**Georgia-ReBORN**](https://github.com/TT-ReBORN/Georgia-ReBORN)——我经常使用的 foobar2000 主题。

我很喜欢它将专辑封面与碟片一起呈现的方式。曾经，我也是实体唱片的收藏者，喜欢拿起一张唱片、欣赏封面和盘面的感觉。但实体 CD 的保存并不容易，即使认真保管，随着年份增长，也难免面临老化和损伤。对我而言，数字化是更适合长期收藏与日常欣赏的方式。

于是，我想把这种数字唱片的展示体验带到椒盐播放器：在享受数字音乐便利的同时，也保留一些收藏和欣赏实体唱片的乐趣，并把它分享给同样喜欢这种感觉的人。

## 目前功能

- **一级详情页**：保留 SPW 原生专辑封面、歌词及播放控制。
- **二级展示页**：点击专辑封面后，放大并居中展示完整封面与右侧 CD；封面不会被挤压成半张图片。
- **本地盘面**：在当前歌曲所在目录中，按 `cd.png → cd.jpg → disc.png → disc.jpg` 顺序查找；高优先级候选无法解码时继续尝试下一项。
- **自动生成盘面**：没有可用本地盘面时，将专辑封面副本裁成圆形 CD，并绘制透明中心孔和轮廓清晰的半透明压环；前方专辑封面仍完整显示。
- **透明图片支持**：使用本地 PNG 时，保留图片已有的透明背景与中心孔，不额外挖孔或叠加压环。
- **页面动画**：封面先放大，随后 CD 从封面后方渐进滑出；点击组合画面返回时先收碟，再调用原生返回操作。倒影跟随同一进度；正常切歌会重新出碟，但不重复缩放封面；快速连切只为最后稳定选择的歌曲出碟。
- **组合倒影**：为封面与 CD 绘制短幅、向下渐隐的倒影。
- 仅读取本地文件，不修改歌曲或盘面原图，也不将自动生成的盘面写入磁盘。

## 安装与使用

当前适配是以 **SPW 1.19.0 Microsoft Store** 为基础。插件使用 SPW 内部绘制接口，SPW 后续版本升级可能需要重新适配。

1. 准备编译好的 `.spmod` 文件。源码 ZIP 不能直接作为插件安装；自行构建的方法见下文。
2. 在 SPW 的插件管理中，使用本地插件导入入口选择 `.spmod` 文件。
3. 按宿主提示授予 `class-transform` 和 `library-read` 权限，然后启用插件、重启 SPW。
4. 播放一首本地歌曲，点击底部播控条进入一级详情页，再点击专辑封面进入二级展示页。
5. 二级页点击封面/CD 组合画面返回：CD 先收回，再回到一级页。出碟中也可以点击返回；重复点击不会叠加返回请求。

切歌后等待约 280 ms 的选择稳定期，并确认封面与盘面查询就绪后播放出碟；这段时间继续切歌会替换待播放请求，不逐首补播。封面来源接管后不会再接受本轮旧节点的反向覆盖。收起到播控条后重新展开时，等待宿主展开完成，再重新播放封面优先和出碟动画；展开过程不消耗动画时间。

直接收起整个播放详情页或停用插件时，会取消未完成的动画与延迟返回，避免残留到迷你播放栏。不同返回入口与快速操作的衔接仍有持续优化空间。

当前安装包文件名为 `SPW_Digital_Disc_V1.0.0.spmod`。源码 ZIP 用于开发和构建，安装时请选择 `.spmod`。

## 本地盘面图片怎么放

把盘面图片放在**音频文件所在的同一文件夹**，例如歌曲在 `D:\Music\某张专辑\01.flac`，则盘面放在 `D:\Music\某张专辑\cd.png`。

| 优先级 | 文件名 |
| --- | --- |
| 1 | `cd.png` |
| 2 | `cd.jpg` |
| 3 | `disc.png` |
| 4 | `disc.jpg` |

如果四个文件同时存在且均可读取，使用 `cd.png`。建议按表中的小写文件名命名；同目录歌曲共用该盘面。目前不递归搜索上级目录或子目录，不支持自定义盘面路径，也不自动从网络下载盘面。

需要透明背景或透明中心孔时，请使用已处理好的 PNG。没有盘面图片也可以使用插件，会自动使用专辑封面生成 CD。

## 制作本地 CD 图片（可选）

不制作盘面图片也能使用插件，插件会自动根据专辑封面生成 CD。若希望展示真实盘面，可按以下步骤准备图片。以 Photoshop 为例，只需掌握选区、图层蒙版和透明图层等基础操作；也可使用支持这些功能的其他图片编辑软件。

**推荐尺寸为 1000 × 1000 像素，使用正方形 PNG 图片。** 其他尺寸的显示效果未经充分验证，不保证与推荐尺寸具有相同的显示效果，建议统一使用这一尺寸。这是推荐制作规格，并非插件只接受该尺寸。

1. **准备清晰的盘面图片**：选用清晰的 CD 扫描图或照片，尽量正面拍摄，避免明显倾斜、变形和强烈反光。先保留原始文件，另存副本进行处理。
2. **抠出 CD 外沿**：用椭圆选区或图层蒙版保留完整碟片，移除外部背景。外沿应平滑，避免残留白边、黑边或锯齿；不要把封面一起保留在盘面图中。
3. **处理中心小孔**：只把真实的中心小圆孔处理为透明。周围塑料压环属于盘面的一部分，可保留原图质感，不要把整片中心区域都挖空。本地图片已有的透明度会保留，插件不会再为它自动挖孔或叠加压环。
4. **整理画布**：将画布裁成正方形，碟片居中、宽高一致，再按比例调整为 **1000 × 1000 像素**。外沿尽量贴近画布边缘，但不要被裁断；避免大量透明留白，否则显示时碟片会显得偏小。不要把椭圆盘面强行拉伸成圆，也不要期待放大小图能补回原本缺失的细节。
5. **保留透明度并导出**：隐藏或删除不需要的背景图层，确认外部背景和中心孔显示为透明棋盘格，而非白色背景。保留可编辑文件后，导出启用透明度的 PNG，命名为 `cd.png`。**JPG 不支持透明背景或透明中心孔**，只更改扩展名不能把 JPG 变成透明 PNG；插件虽可读取 JPG，但不会自动去除其背景。
6. **放置并检查效果**：把 `cd.png` 放在歌曲所在目录。Windows 下注意显示文件扩展名，避免保存成 `cd.png.png`。先在深、浅两种背景上查看外沿、中心孔和残留边缘，再播放该目录中的歌曲进入二级展示页检查实际效果。

完成后的推荐规格：**1000 × 1000 像素、PNG 格式、透明背景、透明中心小孔、碟片居中、外沿完整且无多余留白**。搜索顺序仍为 `cd.png → cd.jpg → disc.png → disc.jpg`；如果希望使用某个较低优先级的文件，先移走同目录中不再使用的高优先级图片。

## V1.0.0 首次发布

仓库从 V1.0.0 开始记录发布版本。本版汇总此前开发阶段已实现的功能，包含以下近期更新：

- **先放大、再出碟**：先呈现放大的封面，再以平滑曲线让 CD 从右侧滑出；组合倒影同步移动。
- **先收碟、再返回**：点击二级组合画面返回时，等待收碟结束后再回到一级页；支持出碟中途返回，重复点击不叠加返回请求。
- **切歌重新出碟**：正常切歌播放出碟动画，封面保持位置与大小；快速连切合并请求，仅为最后稳定选择的歌曲出碟。
- **封面来源锁定**：新封面短暂稳定后接管，排除本轮旧节点的反向覆盖，针对旧、新封面反复交替的频闪路径。
- **重新展开处理**：从二级页收起到播控条后，重新完全展开时启动新的入场动画，避免动画在隐藏期间提前结束。
- **半透明中心压环**：没有本地盘面时，以专辑封面自动生成 CD，中心小孔全透明；压环保留银灰轮廓并减少对图案的遮挡。采用当前确认的压环配色，稍微降低透明度，让压环更实一些。

详细更新见 [CHANGELOG.md](CHANGELOG.md)。后续继续定位偶发旧封面刷新延迟，并完善页面过渡与兼容性。

V1.0.0 以 P4.10.5 为代码与配色基线，安装包沿用既有编译结果更新颜色常量及版本信息，源码已同步。本次版本整理未重新运行完整 Gradle 构建。自行完整编译的方法见下文。

## 编程方式

插件使用 **Java**，沿用 SPW 插件 API、Compose 绘制体系及 Skia 图片解码。通过已定位的 `FullScreenCover` 入口接入，在独立 Canvas 中绘制完整封面与 CD；本地图片异步读取，绘制交接使用 Compose 可观察状态。

## 从源码编译并生成安装包

以下步骤用于自行生成 `.spmod` 插件。仅安装和使用已经编译好的插件时，无需配置这些开发工具。

### 1. 准备构建环境

| 项目 | 要求与用途 |
| --- | --- |
| JDK | 使用本项目沿用的 JDK 25，须包含 `java` 和 `javac` |
| Gradle | 使用本项目沿用的 Gradle 9.8；源码包未附带 Gradle Wrapper，需自行安装 |
| Python | Python 3，Windows 下须能以 `python` 命令运行 |
| SPW 宿主文件 | 已适配的 SPW 1.19.0 Microsoft Store 安装目录中的 `app\ffmpeg-x64.dll` |

宿主文件必须自行从对应 SPW 安装目录提供，不能使用通用 FFmpeg 的同名 DLL 替代。宿主及开发工具不随源码包分发。

### 2. 解压源码并配置 Windows 环境

完整解压源码 ZIP，进入包含 `build.cmd`、`build.gradle`、`MANIFEST.MF` 和 `src` 的目录。不要直接在压缩包中运行脚本。

打开 **命令提示符（CMD）**，按实际安装位置设置环境变量。以下路径仅为示例：

```bat
set "JAVA_HOME=C:\Tools\jdk-25"
set "PATH=%JAVA_HOME%\bin;C:\Tools\gradle-9.8.0\bin;%PATH%"
```

`JAVA_HOME` 指向 JDK 根目录，不是其 `bin` 子目录。上述设置仅影响当前 CMD 窗口；Python 安装目录也需在 `PATH` 中。

检查工具是否可用：

```bat
java -version
javac -version
gradle --version
python --version
```

确认 Java / javac 为 25，Gradle 为 9.8，且 Gradle 显示的运行 JVM 为预期 JDK。若提示命令不存在，先检查安装路径和 `PATH`。Windows 下仅能运行 `py` 而不能运行 `python` 时，需要先修正 Python 的命令路径；现有构建脚本调用的是 `python`。

### 3. 执行编译

在同一个 CMD 窗口中切换到解压后的源码目录，例如：

```bat
cd /d "D:\Projects\SPW-Digital-Disc"
build.cmd "C:\你的SPW安装目录\app\ffmpeg-x64.dll"
```

把第二行的宿主路径替换成真实路径，路径含空格时保留双引号。脚本会调用 Gradle 的 `plugin` 任务，检查宿主组件、编译 Java 源码并打包插件。字节码目标保持为 Java 21，宿主仅作为 `compileOnly` 依赖，不会被打入插件。

若使用 PowerShell，先配置好同样的环境变量，在源码目录执行：

```powershell
.\build.cmd "C:\你的SPW安装目录\app\ffmpeg-x64.dll"
```

`build.cmd` 需要宿主路径参数，不会自动安装开发工具；直接双击不会完成构建。重新生成安装包时，修改源码后再次运行同一条命令即可。

### 4. 找到生成的插件并安装

构建显示 `BUILD SUCCESSFUL` 后，在源码目录的 `dist` 文件夹中找到：

```text
SPW_Digital_Disc_V1.0.0.spmod
```

这就是可供 SPW 导入的插件安装包，无需再将整个源码目录压缩或更改后缀。`build` 目录是编译中间产物，不是安装包。

从 SPW 插件管理中导入此 `.spmod`，授予 `class-transform` 和 `library-read` 权限，启用后重启 SPW。具体页面操作和盘面文件放置方法见本文前面的“安装与使用”和“本地盘面图片怎么放”。

### Linux 下编译

配置 `JAVA_HOME`、将 JDK 和 Gradle 的 `bin` 加入 `PATH`，确保 `python3` 可用，在源码目录运行：

```sh
bash build.sh "/path/to/SPW/app/ffmpeg-x64.dll"
```

同样需要对应的 SPW Windows 宿主文件，产物也位于 `dist/`。Linux 下编译不代表插件可在 Linux 播放器中运行；本项目面向 SPW Windows 版。

### 常见构建问题

| 提示或现象 | 处理方法 |
| --- | --- |
| `Set JAVA_HOME` | 将 `JAVA_HOME` 指向已安装 JDK 25 的根目录 |
| `gradle` / `python` 不是可识别命令 | 安装对应工具并配置 `PATH`，在同一终端重新执行 |
| `Usage: build.cmd ...` | 缺少宿主路径参数，按上面的完整命令调用 |
| 宿主文件不存在或无法作为 ZIP 读取 | 检查是否指向对应 SPW 的 `app\ffmpeg-x64.dll`，而非其他同名文件 |
| `fingerprint mismatch`、缺少宿主类或接口相关编译错误 | 宿主可能不是当前适配版本；使用匹配版本，不要跳过检查强行构建 |
| 构建失败但 `dist` 中已有旧文件 | 旧文件不代表本次构建成功，以本次 Gradle 结果为准 |
